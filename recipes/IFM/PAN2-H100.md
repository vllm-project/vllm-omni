# PAN 2 on H100 and A100 80GB

This recipe runs [PAN2](PAN2.md) text-to-video and image-to-video on 80 GB GPUs
(H100 80GB, H800, A100 80GB). The 55 GiB DiT plus activations for 481 frames
does not fit on one 80 GB GPU, so one GPU uses distributed layerwise offload and
several GPUs use tensor parallelism.

## Capacity

The profiles are sized for the longest supported output, 704x1248 and 481
frames. Peak memory is per GPU (first GPU / others).

Distributed layerwise offload keeps the DiT and text encoder in pinned host
memory, so the server needs a large amount of system RAM, and each CFG-parallel
branch adds its own copy. Raising `--dlo-resident-layers` keeps more DiT blocks
on the GPU, which reduces host-to-GPU traffic, but uses more GPU memory;
re-measure before raising it.

| GPUs | Peak memory (481 frames) |
| --- | ---: |
| 1 GPU | 73.2 GiB |
| 8 GPUs | 74.6 / 61.1 GiB |

## 1 GPU

34 of the 48 DiT blocks stay on the GPU; the rest stream from pinned host
memory.

```bash
pip install git+https://github.com/ifm-ai/pan2-guardrail  # PAN 2 guardrails
vllm serve IFM/PAN2 --omni --port 8091 \
  --vae-use-tiling \
  --enable-distributed-layerwise-offload --dlo-no-use-allgather --dlo-resident-layers 34 \
  --enforce-eager \
  --stage-overrides '{"0": {"model_config": {"offload_guardrail_models": true}}}'
```

## 8 GPUs

No offload. Tensor parallelism splits the DiT four ways within each CFG branch.

```bash
pip install git+https://github.com/ifm-ai/pan2-guardrail  # PAN 2 guardrails
vllm serve IFM/PAN2 --omni --port 8091 \
  --num-gpus 8 \
  --tensor-parallel-size 4 --cfg-parallel-size 2 \
  --vae-patch-parallel-size 8 --vae-parallel-mode tile
```

Send requests as shown in [PAN2](PAN2.md#requests).
