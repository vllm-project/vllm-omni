# RFC: RL HTTP Interfaces for vLLM-Omni

Control-plane interfaces carry commands, topology, identifiers, and small status results. They do not carry bulk model tensors. For weight synchronization, HTTP calls flow through `AsyncOmni -> Orchestrator -> StageClient -> Worker`; the trainer and workers then move tensor bytes through NCCL, CUDA IPC, shared storage, or another negotiated data plane. Diffusion rollout is also handle-first: colocated trainers receive shared-memory handles plus small metadata instead of rematerialized training tensors in the HTTP process. Mirroring a vLLM route does not imply semantic compatibility: multi-stage operations must identify their stage/component scope and return acknowledgements from every affected stage. The implementation is developed on a dedicated feature branch, while interface-specific extensions are deferred to sub-issues.

| Interface | Role | vLLM | vLLM-Omni baseline | Why the interface is needed | How the data plane works |
| --- | --- | --- | --- | --- | --- |
| `POST /pause` | Control | Supported: `mode=abort\|wait\|keep` | Partial: drain/abort behavior, cache reset, and stage acknowledgements are incomplete | Weight mutation must not race with admission or active generation. The endpoint establishes a pipeline-wide barrier and must not report success until every affected stage is paused | No tensor transfer. The orchestrator stops admission, sends lifecycle RPCs to stage schedulers, waits for per-stage acknowledgements, and optionally asks workers to release cache blocks |
| `POST /resume` | Control | Supported | Basic support | A trainer needs an explicit point at which updated workers may accept rollout traffic again | No tensor transfer. The orchestrator changes scheduler admission state only after all required stages are ready |
| `GET /is_paused` | Control/status | Supported | Partial: mainly frontend state | A successful HTTP response from `/pause` is insufficient if a stage has not reached the barrier; the trainer needs observable completion | Reads small state records from the orchestrator/stages; no model data moves |
| `POST /abort_requests` | Control | Supports selected IDs and abort-all | Partial: selected IDs work; inherited abort-all assumes `AsyncLLM` | Removes stale, timed-out, or failed rollouts and ensures they do not keep stage resources during an update | The orchestrator maps external IDs to internal stage requests, sends cancellation RPCs, and releases request/KV/latent state locally |
| `POST /init_weight_transfer_engine` | Control-plane setup | Supported | Missing usable implementation | Trainer and inference workers must agree on transport, ranks, addresses, buffer layout, and explicit stage/component targets before bytes can move | HTTP distributes setup metadata only. Targeted workers create NCCL communicators, import IPC capabilities, or prepare artifact readers; no model weights are transferred yet |
| `POST /start_weight_update` | Control | Supported | Present but currently a no-op | Opens one coordinated update and prevents chunks from being applied outside an active update window | Workers select the target model/component, prepare loaders or temporary buffers, and enter the required synchronization state; no bulk tensor transfer yet |
| `POST /start_draft_weight_update` | Control | Supported | Missing | The same transfer protocol needs an unambiguous way to update speculative draft weights instead of target-model weights | Identical to `/start_weight_update`, but workers bind following tensor chunks to the draft model |
| `POST /update_weights` | Control trigger for data transfer | Supported: accepts `update_info` and supports chunks | Missing | Tells the workers selected during initialization which chunk to receive and prevents a weight payload from being applied to the wrong stage or component | HTTP carries names, shapes, offsets, handles, and transport metadata. Tensor bytes move directly trainer-to-worker through NCCL broadcast, CUDA IPC mappings, or an artifact reader, then are copied into the selected model parameters |
| `POST /finish_weight_update` | Control/commit | Supported | Incompatible no-op implementation | A transfer is not usable until all chunks are applied, worker collectives finish, and old cache/graph state is invalidated | Workers run loader post-processing and synchronization barriers. Only small acknowledgements return over HTTP; no model tensors return |
| `GET /get_world_size` | Control/topology | Supported | Partial: one engine-wide value cannot describe heterogeneous stages | The trainer needs topology for the specific stage/component target when constructing transfer groups; a compatible-looking global value can build the wrong communicator | Reads configuration and live membership metadata only. Omni responses need per-stage TP/PP/DP/replica details in addition to any vLLM-compatible aggregate; no runtime tensor transfer |
| `POST /get_weights_checksum` | Control/verification | Missing | Missing | HTTP success proves that a call returned, not that every worker installed identical weights. Checksums detect missing chunks, corruption, and inconsistent replicas before resume | Each worker reads its local selected parameters and computes hashes. Only component/worker hash strings are returned and compared; weight tensors stay on the worker |
| `POST /rollout/generate` | Data-plane coordination | Not applicable: LLM rollout uses existing generation interfaces | Missing for Diffusion stages | Diffusion policy-gradient training needs more than a generated image/video: it also needs log probabilities and selected denoising state without rematerializing large tensors through the HTTP server, duplicating host memory, and risking host OOM | The request schedules normal GPU denoising. For colocated RL, workers place trajectory latents, timesteps, and log probabilities in shared memory and return handles with shape, dtype, ownership, and release metadata. Object-store transport and bounded remote payloads are separate extensions |
| `POST /reset_prefix_cache` | Control | Supported | Partial: logs a warning and returns success | AR cache entries were computed with old weights and can make post-update output inconsistent | Workers delete local prefix/KV block metadata and free or recycle the associated device memory; HTTP carries no cached tensors |
| `POST /reset_mm_cache` | Control | Supported | Partial: logs a warning | Cached multimodal preprocessing or embeddings may depend on updated components | Workers invalidate local multimodal cache entries; any later input recomputes them through the normal inference data path |
| `POST /reset_encoder_cache` | Control | Supported | Partial: logs a warning | Encoder outputs created with old weights must not be reused after an encoder update | Workers drop cached encoder tensors and metadata locally; they are recomputed on the next request |
| `POST /sleep` | Control | Supported: `level` and `mode` query parameters | Incompatible inherited route; Omni exposes `/v1/omni/sleep` | Training and inference may share accelerators, so the trainer needs a coordinated way to reclaim inference memory | Level 1 moves weight pages from GPU to pinned CPU memory; level 2 unmaps/discards configured GPU allocations. The endpoint sends commands and returns freed-byte/status acknowledgements only |
| `POST /wake_up` | Control | Supported: repeated `tags` query parameter | Incompatible inherited route; Omni exposes `/v1/omni/wakeup` | Rollout cannot resume until released weights, buffers, and required caches are available again | Workers remap pages, copy weights from CPU to GPU, or reload safe artifacts, then synchronize the device before acknowledging readiness |
| `GET /is_sleeping` | Control/status | Supported | Partial: mainly frontend bookkeeping | The trainer must distinguish “sleep requested” from “GPU memory actually released/restored” | Collects small worker state and memory counters; no model data moves |
| `POST /v1/load_lora_adapter` | Control trigger for artifact loading | Supported when runtime LoRA updating is enabled | Partial: stage/component targets and per-stage results are missing | Online RL may update only an adapter, but the same adapter name can apply to different AR or Diffusion components; route-level compatibility must not silently broadcast to incompatible stages | HTTP carries adapter identity/path, explicit targets, and options. Targeted workers read adapter tensors from local/shared/object storage or a negotiated transfer channel, install them into LoRA buffers, and acknowledge independently |
| `POST /v1/unload_lora_adapter` | Control | Supported when runtime LoRA updating is enabled | Partial: stage/component targets are missing and per-stage failures can be hidden | Frees adapter slots and prevents a stale policy adapter from being selected, without removing an adapter still required by another stage/component | Targeted workers remove local adapter buffers and routing metadata and acknowledge independently; only status travels over HTTP |
| `GET /server_info` | Control/discovery | Supported in development mode | Does not describe Omni RL capabilities | Trainers should negotiate capabilities before mutating the server instead of assuming that route presence means support | Returns configuration and capability metadata only; it neither initializes a transport nor moves tensors |
