# L6: component state, headroom and recommendations

## Inputs

Use the L0 contract, complete L1 path, layer findings and raw artifact lineage.
Read [bounds and impact](bounds-and-impact.md) before quantifying space and
[reporting](reporting.md) before delivery. The machine schema remains
[evidence.md](../evidence.md); recommendation fields remain
[diagnostics.md](../diagnostics.md#recommendation-card-contract).

## Procedure

1. Audit coverage across phases, shapes, ranks, regimes and completion boundaries.
   Unknown work remains visible even when all recorded events are classified.
2. For each component state execution efficiency AND structural work state.
   Necessary, near-reference work differs from an efficient but redundant kernel.
3. Separate observation, mechanism inference, reference gap, conditional scenario,
   model prediction and measured/quality-validated gain.
4. Recompute completion under candidate changes where dependencies are known.
   Include replacement costs, new bottlenecks, capacity and interactions; do not
   add independent reference gaps or overlapping layer shares.
5. Rank evidence-backed recommendations by plausible exposed impact, confidence,
   risk and validation effort. Evidence repair is P0; likely material opportunities
   are P1; uncertain/lower-leverage exploration is P2. Explain the order in prose.
6. For every layer, record what is mature, actionable, uncertain and inapplicable.
   A complete report can truthfully conclude that some areas cannot yet be judged.
7. Evaluate a scoped stop proposal only against predeclared scope/threshold,
   measurement precision, reviewed search/residual argument and independent approval.
   Otherwise give the next discriminating experiment, not a generic optimization menu.

## Decision boundaries

- Near a matched reference is not globally optimal.
- Low exclusive cost is low current direct leverage, not no throughput/capacity
  effect and not proof that the component is efficient.
- A completed structural review describes the searched space, not all possible
  future algorithms. No candidate found does not establish saturation.
- Quality acceptance is separate. A candidate with small kernel error can still
  fail full image/video quality or supported-shape behavior.
- Budget exhausted means budget stop, not performance saturation.
- The helper only proposes `STOP_REVIEW_REQUIRED`; it never authorizes RSI to
  stop, and its serialized certified global bound remains null.

## Handoff

Deliver ordered L0-L6 findings, the component roll-up, recommendation queue,
non-additive impact assumptions and explicit unknowns. Keep a separately reviewed
bound derivation as an artifact if one exists; do not relabel empirical references
as certified bounds to satisfy report fields. No implementation is performed by
the analysis handoff. Record useful rejected hypotheses in the casebook protocol.
